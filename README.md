# Quadratic DSA Challenge Generator

This project generates CTF-style DSA challenges with intentionally weak nonce generation. The visible nonce recurrence is designed to look nontrivial, but it always collapses to a quadratic equation in the secret key over a prime field.

The goal is to create challenge instances that appear more complex than a simple linear recurrence while still remaining algebraically solvable.

## Idea

Digital signature schemes such as DSA or ECDSA depend critically on secure nonce generation. If nonces are weak, predictable, or generated by a reversible deterministic process, the private signing key can often be recovered.

This generator builds challenges around exactly that weakness:

- a symbolic recurrence is generated from affine terms and constants,
- the final visible relation is kept quadratic in the hidden secret,
- each challenge is instantiated over a random prime field,
- a matching solver script reconstructs the quadratic relation and recovers the flag.

Although the expressions can look noisy, the underlying structure remains of the form $ax^2 + bx + c \equiv 0 \pmod q$.

## Repository Layout

- `generator.py`: core symbolic formula generator and verifier.
- `run_from_config.py`: convenient config-based entry point for experimenting with one generated formula.
- `build_generated_dsa_challenges.py`: builds full challenge pairs consisting of a generated server and a matching solver.
- `sample_server.py`: reference style for the generated challenge server.
- `sample_solution.py`: reference style for the generated challenge solver.
- `generated_challenges/`: output directory for generated challenge files.

## What Gets Generated

For each challenge run, the builder creates:

- a DSA-style server with a deterministic `get_next_nonce()` recurrence,
- fresh DSA parameters `p`, `q`, `g`, and public key `y`,
- a generated flag,
- a solver script tailored to that exact challenge instance.

The solver uses the emitted signatures to reconstruct the quadratic equation and recover the private key, which is then decoded back into the flag.

## Typical Workflow

Generate and inspect a single symbolic formula:

```bash
python3 run_from_config.py
```

Generate full server/solver challenge pairs:

```bash
python3 build_generated_dsa_challenges.py
```

Run one generated server manually:

```bash
cd generated_challenges
python3 challenge_001_server.py
```

Run the matching solver:

```bash
python3 challenge_001_solution.py
```

## Design Goal

The design target is not cryptographic realism. It is controlled algebraic weakness.

Each generated instance should:

- look structurally different from the others,
- contain a recurrence that appears complicated at first glance,
- still reduce to a quadratic relation in the secret,
- remain solvable by a corresponding script without manual symbolic work.

That makes the project useful for generating families of related CTF challenges with adjustable complexity while preserving a predictable solution path.
